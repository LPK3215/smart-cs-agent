# 5. 可复用资产

以下思路/模式可直接迁移到你的其它 LLM/Agent 项目。结合"关注的核心问题"——这里假设关注：**如何构建一个可演示、可观测、可降级、易扩展的 AI Agent 应用**。

## 5.1 立即可抄的模式

| 模式 | 来源 | 迁移用法 |
|---|---|---|
| **Protocol + 工厂降级**数据源 | `services/base.py` + `__init__.py` | 任何需要 mock/real 切换的 Agent 工具（订单/库存/CRM）直接套 |
| **SSE 流式 + 非流式降级** | `main.py` + `chat.ts` | 前端展示 Agent 思考过程时，先 SSE，失败回退 JSON |
| **结构化元标签解耦** | `agent.py` `parse_agent_output` | 让 LLM 同时产出"给用户的话"和"给系统的元数据"（intent/confidence），避免二次解析 |
| **三级 Guardrails（BLOCK/WARN/SAFE）** | `guardrails.py` | 任何面向用户的 LLM 都该有输入校验 + 内容安全 + 输出净化三层 |
| **记忆分层（窗口+抽取+画像）** | `memory.py` + `user_context.py` | 长对话 Agent 的上下文管理样板 |
| **工具审计表（duration_ms/success）** | `database.py` `tool_calls` | Agent 可观测性最小实现，可用于成本/延迟优化 |
| **多模型路由省 token** | `agent.py` `_route_model` | FAQ/简单类走轻量模型，复杂类走主力模型 |

## 5.2 可复用的代码片段（概念级）

1. **LangChain v2 事件流 → SSE 映射**：`astream_events(api_version="v2")` 解析 `on_chat_model_stream`/`on_tool_start`/`on_tool_end` 是流式 Agent UI 的标准做法，可直接复用骨架。
2. **记忆摘要 prompt**：`memory.py` 的 `SUMMARY_PROMPT` 是中文客服场景的现成摘要模板。
3. **注入检测正则集**：`guardrails.py` 中英文双覆盖的 injection/safety 正则，可作为自己项目的起步黑名单（注意需配合语义检测才够安全）。

## 5.3 不值得抄的（反面教材）

- **字符哈希当 embedding**（`vector_store.py`）：仅适合离线 demo，真实项目务必换 sentence-transformers / OpenAI embeddings / 本地 bge 模型。
- **内存 FAISS 不落盘**：演示可以，生产必须用持久化向量库。
- **`.env` 提交密钥**：务必 gitignore + secrets 管理。

## 5.4 迁移到"我的项目"的第一步建议

若你要做类似东西：**第一步抄 `services` 抽象层 + Guardrails 三层 + SSE 降级骨架**（这三者与具体业务无关、最通用）；**第二步把 `vector_store` 换成真 embedding + 持久化向量库**；**第三步补 `pytest` + `Dockerfile`** 让项目达到"可交付"水准。
