# 2. 核心数据流

## 2.1 启动初始化（`main.py` startup 事件）

```
@app.on_event("startup")  [main.py L99-110 附近]
  ├─ Database().initialize()        → 建 7 张表（database.py L300+）
  ├─ knowledge_base.initialize()    → 加载 FAQ 文本、分块、写 FAISS
  └─ get_vector_store()             → 初始化检索器单例
```

`knowledge_base.initialize()`（`knowledge_base.py`）：把内置 FAQ 字符串按 `【` 分隔成块 → `vector_store.add_texts()` 生成 FAISS 索引（内存驻留，未持久化到磁盘 ⚠️ 见坑）。

## 2.2 一次流式对话的完整链路（核心路径）

入口：`POST /api/chat/stream`（`main.py` L238 附近）→ `chat_stream()` 协程。

```
① 鉴权
   get_current_user(request)                [auth.py L59]
   → 解 JWT → 查 user

② 落库用户消息
   add_message_db(session_id, 'user', text) [database.py]

③ 构建上下文 build_context()                 [agent.py]
   ├─ get_user_context(user_id)             [user_context.py L202]  (画像+记忆)
   ├─ get_recent_messages(session_id)       [database.py]           (近期消息)
   └─ (session_summary 注入系统提示)

④ 输入护栏
   validate_input(text)                     [guardrails.py L72]  (长度/注入 BLOCK/WARN)
   check_content_safety(text)               [guardrails.py L99]  (危险内容→转人工)

⑤ Agent 执行（核心）
   run_agent(user_input, context)           [agent.py]
     → create_agent(llm, tools, checkpointer, ...) [LangChain 实验性 API]
     → agent.ainvoke({"messages":[...]}, config={"recursion_limit":MAX_ITERATIONS})
     → 内部 ReAct 循环：LLM 推理 → tool_call → 工具执行 → 观察 → 再推理
     → 每个工具返回被记录（tool_calls 表）

⑥ SSE 流式输出 generate_response_stream()   [agent.py]
     → astream_events(api_version="v2")      [LangChain v2 事件流]
     → 解析事件：
        on_chat_model_stream → token         → yield SSE "data: {...token...}"
        on_tool_start        → tool_start    → yield SSE (工具名+输入)
        on_tool_end          → tool_end      → yield SSE (工具输出)
     → 结束时 yield done 事件 (intent/source/confidence/need_human/trace)

⑦ 收尾落库
   analyze 元结果 → add_message_db('bot', reply, intent, source, confidence)
   update_session(...) / 必要时 mark transferred
   （tool_calls 在工具执行时即时入库，含 duration_ms）

⑧ 前端消费
   utils/sse.ts parseSSEStream(response)
     onToken    → chatStore.streamingContent 累加（打字机）
     onToolStart/End → 渲染工具调用轨迹
     onDone     → chatStore 重拉 sessions/messages 刷新真实数据
   ❌ 若 SSE 失败 → 降级 api.sendChatMessage() 非流式 [chat.ts]
```

## 2.3 非流式对话链路

`POST /api/chat`（`main.py` L178 附近）→ `chat()`：复用 ①②③④⑤，但用 `run_agent()` 同步等结果，直接返回 `{reply, intent, source, confidence, need_human, trace, tool_calls}` JSON。前端 `chat.ts` 仅在 SSE 失败时才走此路——**降级容错是关键设计点**。

## 2.4 会话关闭 / 记忆提取链路

`POST /api/sessions/{id}/close`（`main.py`）→ `close_session()`：
```
update_session(status)                  [database.py]
summarize_history(history)              [memory.py L54]  (LLM 摘要旧对话)
extract_memories_from_session(...)      [user_context.py L49]  (抽取意图/转人工信号→user_memories)
update_user_profile(user_id)            [user_context.py L118]  (聚合画像 JSON)
```
这些记忆在下次对话经 `build_context → get_user_context` 注入系统提示，实现跨会话个性化。

## 2.5 管理后台 / 可观测链路

`GET /api/analytics`（`main.py` L420 附近，需 `require_admin`）→ `get_analytics()`：
```
聚合 sessions / messages / ratings / tool_calls 四表
  → intent_stats (意图分布)
  → source_stats (faq/db/agent 占比)
  → resolution_stats (resolved/transferred)
  → rating_stats (均分+分布)
  → tool_stats (调用次数/平均耗时/成功率)
  → conversations[] (逐会话明细，含 intent/rating/source)
```
`GET /api/tool-audit` → 工具调用审计明细（含 `duration_ms`、`success`，支持按 tool/status 过滤）。前端 `admin.ts` 消费后由 ECharts 组件（IntentChart/SourceDonut/RatingChart/ResolutionBars/ToolStatsTable/ConversationTable）渲染。

## 2.6 RAG 检索链路（search_faq 工具内部）

```
query_faq(question)                     [agent.py 内工具]
  → vector_store.search(question, top_k=3)   [vector_store.py L136]
      → _encode(text) numpy 哈希 → faiss index.search(top_k=5)
      → 返回最相似 FAQ 块
  → 拼成上下文注入 Agent 提示
  → source 标记为 'faq'
```
注意：`vector_store.search` 实际返回 top_k=5（L137 `k=5`），与 `query_faq` 传入的 `top_k=3` 不一致 ⚠️ 见坑。
