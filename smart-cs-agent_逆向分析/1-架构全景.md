## 1.2 模块依赖关系（引用方向）

| 模块 | 被谁依赖 | 依赖谁 |
|---|---|---|
| `main.py` | —(入口) | auth, guardrails, agent, database, memory, user_context, models |
| `agent.py` | main | memory, user_context, vector_store, services, config, auth |
| `memory.py` | agent | config, database(`get_db`) |
| `user_context.py` | agent, memory | database(`get_db`) |
| `guardrails.py` | main, agent | config |
| `vector_store.py` | agent, knowledge_base | faiss, numpy, config |
| `knowledge_base.py` | main(启动) | vector_store, config |
| `services/__init__.py` | agent(工具调用) | config, services/mock_service(或 real_service) |
| `database.py` | 几乎所有模块 | aiosqlite, config |
| `auth.py` | main | jose, bcrypt, database |

**依赖基本单向向下**，无循环依赖，分层健康。唯一"跨层"的是 `agent.py` 同时耦合 config/services/vector_store/memory——属于编排层的合理耦合。

## 1.3 核心抽象

1. **数据库访问**：`get_db()` 单例协程（L89-128），所有模块通过它拿 `aiosqlite.Connection`，全程 async。
2. **服务接口（Protocol）**：`services/base.py` 定义 `OrderService`/`RefundService`/`TroubleshootService` 三个 `@runtime_checkable Protocol`，mock/real 实现同一接口（`services/__init__.py` 按 `DATA_SOURCE` 选择，real 缺失则降级 mock，L18-53）。这是最值得学习的**可扩展抽象**。
3. **Agent 工具**：`agent.py` 内 `query_order`/`check_refund`/`troubleshoot`/`search_faq`/`finish` 五个 `@tool` 函数，通过 `create_agent` 注册（L 附近 `tools = [...]`）。
4. **向量检索器**：`VectorStore` 类封装 FAISS `IndexFlatL2` + numpy 文本哈希做 ID 映射（`vector_store.py` L44-191）。
5. **前端状态**：Pinia 三 store（auth/chat/admin），单向数据流。

## 1.4 前端架构（`smart-cs-web/src/`）

```
main.ts → createApp → use(pinia) + use(router)
App.vue → 按 route.meta.layout 选布局: blank / user / admin
router/index.ts → beforeEach 鉴权守卫 (verifyToken / 角色校验)
  ├─ /login,/admin/login        (blank)
  ├─ /chat,/profile             (user  → AppLayout → ChatView/ProfileView)
  └─ /admin                     (admin → AppLayout → AdminView)
stores/: auth.ts(持久化 token) · chat.ts(SSE 流式状态) · admin.ts(聚合派生)
utils/: api.ts(fetch 封装+barer+401) · sse.ts(parseSSEStream)
api 命中路径：Vite proxy /api → :8000 (vite.config.ts)
```

前端组件仅通过 store 调 `utils/api.ts`，store 调后端，**组件不发直接 HTTP 请求**，单向数据流清晰。
